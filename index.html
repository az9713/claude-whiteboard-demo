03

What is not solved

Capability keeps climbing. Judgment does not. This gap is where humans still win.

Decisions nobody can check

Ask for a UI and it still looks like generic LLM output, even with Fable 5.2. Better, but not there.

Product judgment

Models do not make better product decisions than people. Care and taste show clearly in what you ship.

Taste and direction

A product refined through many careful prompts beats "Opus, make me a chat app" by a wide margin.

Hands-off is a trap

Stop watching the output and quality rots. You still put in real effort, just at a higher level.

Ben's workflow is a loop. Each pass raises quality, and each failure becomes a permanent fix.

STEP 1

04a

The harness, explained

A harness is a safe practice copy of the real thing. The agent can test its own work against it thousands of times, with no human watching.

The spec

YouTube's public API docs: what you can request, and what comes back.

→agent copies

The fake API

A small pretend YouTube server built from the spec, returning believable made-up data. A bot keeps it in sync when the spec changes.

→tests against

The real app

The agent builds against the fake, runs it, sees what breaks, fixes it. Repeat.

Why not use the real YouTube? Real APIs need keys and logins a cloud sandbox doesn't have. They also have quotas, change under you, and can't be reset. A fake is free, instant and always in a known state, so the agent can loop for hours on its own. The FPS game uses the same idea: a CLI plus screenshots let the agent move the character, jump around the world and see whether a change worked, instead of struggling to click through a 3D game.

04b

The #1 skill in 2026

Ben quotes Mario, creator of the Pi coding agent: the most important skill is still telling your agents, "No, not like this." In practice that means three moves.

1

Notice

Actually look at the output. Your domain knowledge is what spots what's off.

2

Reject

Say no, plainly and specifically. Don't settle for good enough.

3

Engineer it out

Add a test, rule or tool so the same mistake can't come back.

Why it's #1: agents now write the code, but they still can't tell good from good enough. The person who keeps saying no, and turns each no into a permanent guardrail, gets quality that compounds.

Weak correction

"This is wrong, try again."

The agent guesses, and the same bug returns next week.

Strong correction

"The button overlaps the title on mobile. Fix it, then add a screenshot check at 375px."

Fixed now, and it can't come back.
